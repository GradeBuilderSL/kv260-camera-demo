# DPU Profiling: `Mem IO(MB)` and `Mem Bandwidth(MB/s)`

Explains the meaning of these two columns in the **DPU Summary** section of
`profile_summary.csv`, generated by Vitis AI vaitrace / XRT profiling.

## What is `Mem IO(MB)`?

`Mem IO(MB)` is a **per-single-run constant** that represents the total DDR
memory traffic produced by one execution of a DPU kernel (subgraph):

```
Mem IO = LdFM  +  LdWB  +  StFM
```

| Component | Description |
|-----------|-------------|
| **LdFM** | Load Feature Maps — input activation tensors read from DDR |
| **LdWB** | Load Weights/Biases — model parameters read from DDR |
| **StFM** | Store Feature Maps — output activation tensors written back to DDR |

The value is **identical for every inference run** because the kernel's tensor
shapes and weight sizes are fully determined by the compiled model topology.
It does not depend on input data values.

### Example (MobileNet V2 on DPUCZDX8G)

From a 110-run benchmark (`profile_summary.csv`):

| Kernel | Mem IO (MB) | Mem BW (MB/s) | Avg Time (ms) |
|--------|-------------|---------------|---------------|
| subgraph_263 | 0.599 | 1251.4 | 0.490 |
| subgraph_271 | 0.481 | 953.7 | 0.516 |
| subgraph_417_bias_new | 1.224 | 4005.8 | 0.313 |
| **All 36 subgraphs (sum)** | **9.229** | — | — |

The total **9.229 MB** is the DDR traffic for one complete MobileNet V2
inference across all DPU subgraphs.

## What is `Mem Bandwidth(MB/s)`?

`Mem Bandwidth` is the **mean memory bandwidth** across all runs for that
kernel, computed per-sample before averaging:

```
Mem Bandwidth = mean( Mem IO / t_i )   for each run i
```

This is **not** the same as `Mem IO / Avg Time`:

```
mean(Mem IO / t_i)  ≠  Mem IO / mean(t_i)
```

The difference arises from Jensen's inequality (`mean(1/t) ≥ 1/mean(t)`).
In practice the reported bandwidth is ~2–3% higher than `Mem IO / Avg Time`,
and the ratio is consistent across all kernels (observed ~0.977 in MobileNet
V2 profiling), confirming that XRT computes bandwidth per-sample first and
then averages.

## Relationship to DDR Bandwidth (`vitis_ai_profile.csv`)

`profile_summary.csv` reports per-kernel DPU-side memory traffic.
`vitis_ai_profile.csv` reports the raw DDR controller time-series
(`DDRC_PORT_S{1-5}_Read/Write` in MB/s) captured by XRT hardware counters.

These are complementary views:

| File | Granularity | What it measures |
|------|-------------|-----------------|
| `profile_summary.csv` | Per DPU kernel | Logical memory traffic (LdFM + LdWB + StFM) per run |
| `vitis_ai_profile.csv` | ~10 ms time buckets | Physical DDR controller read/write bandwidth on each AXI port |

The per-kernel Mem IO values should be consistent with the peak DDR bursts
visible in `vitis_ai_profile.csv` during active DPU subgraph execution.
